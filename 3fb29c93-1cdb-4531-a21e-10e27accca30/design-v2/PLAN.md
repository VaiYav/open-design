## 2. Концепция v2

**«Flow v2 — операторский inbox-first workspace на едином современном языке».**

Три структурных хода:

1. **Слияние двух слоёв.** В v1 shell (ink #191243, 5px, контролы 38px, серые поверхности) и chat-слой (slate/indigo, 14–18px, glass) — два разных продукта в одном окне. v2 берёт уточнённый язык chat-слоя как базу всего продукта, сохраняя бренд-палитру.
2. **Консолидация кампаний.** 4 параллельные зоны (auto_sendings, icebreakers, invites, newsfeeds) + 5 типов блэклистов — это одна и та же структура «пивот → per-lady → табы → форма». v2 собирает их в одну зону **Campaigns** с единым per-lady контекстом; типы рассылок — под-разделы. 27 файлов v1 → ~12–14 экранов v2 без потери покрытия (маппинг в манифесте).
3. **State-machine атлас как deliverable.** Каждый экран — один файл, несущий все свои состояния; лаунчер = браузер состояний (дерево экранов → чипы состояний → viewport).

## 3. Визуальное направление (моё решение, делегировано)

База — **Product Design System** (уже активна): white `#ffffff` bg, slate-50 `#f8fafc` surface, gray-900 `#111827` fg, gray-500 `#6b7280` muted, gray-200 `#e5e7eb` border, primary blue `#5862de`, lavender `#9f63ca` secondary. Open Sans display+body, mono для цифр/ID.

Поверх — уточнённая геометрия chat-слоя v1: радиусы 6/14/16/18px + pill для primary, контролы 44px в продуктовых поверхностях, 1px бордеры, layered тени, hover = lift/shadow (никогда не светлеющий текст), focus = 3px indigo-ring @25%. Анти-паттерн DS соблюдаем: `#5862de` и `#6366f1` не встречаются в одном компоненте — единый акцент `#5862de`.

Шелл v2: левый nav-rail (иконки + лейблы, коллапс до 56px), верхний slim-бар с lady-context switcher и статусами. Фон `#f8fafc`, контент — белые карты 16px.

**Dark theme — обязателен с Phase A.** `tokens-v2.css` сразу пишется двухслойным: `:root` (light) + `[data-theme="dark"]` — тёмная палитра выводится из зарегистрированных токенов через `oklch(from var(--bg) …)` / инверсию L-канала, без новых hex-литералов. Тогл темы живёт в шелле (slim-бар) и в атласе (`?theme=dark` пробрасывается в iframe). Каждое состояние каждого экрана проверяется в обеих темах — state-матрица считается зелёной только ×2.

Аватары/медиа: нейтральные soft-shape аватары по DS (персонажи вымышленные — фото не требуются). Платформенные логотипы — из `design-copy/assets/logos/` как есть.

## 4. Архитектура стейт-машины

```
design-v2/
├── PLAN.md                  ← этот файл
├── index.html               ← атлас: дерево экранов · чипы состояний · iframe viewport · deep-links
├── manifest-v2.json         ← { screen: id, file, zone, title, v1File, states[] } — источник дерева
├── assets/
│   ├── tokens-v2.css        ← палитра + геометрия + компонентные стили v2
│   ├── app.js               ← табы/модалки/меню/toast (как в v1) + state engine
│   ├── stateful.js          ← ?state= · ?theme= · чип-переключатель · data-view visibility
│   ├── components.js        ← fixture-driven рендер: table, list, tabs, pagination, empty/error/skeleton
│   └── fixtures.js          ← демо-данные (леди, чаты, шаблоны) — populated/empty/error наборы
└── <screens>.html           ← по одному файлу на экран, все состояния внутри
```

**Механика состояний.** В разметке экрана блоки помечены `data-view="populated|loading|empty|error|…"`. `stateful.js` читает `?state=` из URL, ставит `data-state` на `<html>`, показывает активный view и рисует встроенный переключатель состояний (плавающая панель). Внутри атласа iframe получает `screen.html?state=x&chrome=0` — чипы дублируются в хедере атласа. Deep-link: `index.html?screen=chats&state=empty`.

**Канонический набор состояний** (per-type, расширяется доменными):

- list/table/pivot: `populated · loading · empty · error`
- 3-pane workspace: `no-selection · loaded · loading · error · send-failed`
- формы (create/edit): `default · validation · submitting · success`
- модерационные списки: состояния табов = состояния экрана (pending/approved/declined поверх populated)
- verify→commit флоу: `verify-step · commit-step`

**Fixture-driven контент.** Повторяющиеся части (строки таблиц, элементы списков, чипы) рендерятся `components.js` из `fixtures.js` — состояние = другой fixture. Статический HTML хранит шелл и структуру. Это держит 59-экранный объём управляемым и гарантирует консистентность.

### Vision-экраны «new in v2» — новые фичи поверх редизайна

Это питч-слой: показываем, куда продукт может пойти, а не обещания из бэклога. Каждый экран помечен бейджем `new in v2` в атласе и `vision: true` в манифесте; набор состояний — тот же канонический, что у их типа.

| Экран | Суть | Опирается на |
|---|---|---|
| `home` — Command Center | Смена с высоты птичьего полёта: непрочитанные по платформам, SLA-таймеры ответов, статус активных кампаний, лента алертов. Новый дефолтный лендинг после login | chats + campaigns + alerts |
| `inbox` — Unified Inbox | Все чаты и письма всех платформ и леди в одном триаж-потоке: фильтры платформа/леди/статус, bulk-действия, переход в тред | chats + mails |
| `chats` state `copilot` — AI Copilot | Панель «Beloved» прямо в 3-pane: драфт ответа, саммари переписки, выбор тона, перевод. Состояние, не отдельный файл | chats + omniscience |
| `campaigns-performance` | Аналитика кампаний: sent/opened/replied по шаблонам и платформам, тренды, сравнение типов рассылок | campaigns + statistics |
| `admin-coverage` — Coverage Map | Теплокарта покрытия смен: операторы × часы, подсветка дыр в расписании, назначение из того же экрана | admin schedules |
| `alerts` — Notifications Center | Центр событий: ошибки доставки, системные лимиты, срабатывания блэклистов, бэклог модерации — с переходами в зону-источник | все зоны |
| `monitor` — Live monitor | Ops-борд реального времени: здоровье 5 платформ, sends/час, живой поток событий, кто на смене | admin + alerts |
| `lady-360` | Единый профиль леди: аккаунты, расписание, блэклисты, покрытие кампаниями, фидбек на её сообщения | tools + admin |
| `scorecard` — My scorecard | Личная карточка оператора: темп смены, скорость ответа, полученные оценки, сравнение с медианой команды | workspace + feedback |
| `planner` — Campaign planner | Недельный календарь отправок с capacity-метрами, quiet-hours и очередью незапланированных черновиков | campaigns |
| `admin-message-feedback` | Управление фидбеком FLOW-8555: Overview/Weak cases, coverage, reason-чипы, reviewers | feedback |
| `omniscience` state `ab` | Слепое A/B-ревью двух моделей на одном промпте, reveal после голосов | omniscience |

## 6. Фазы и порядок работ

- **Phase A — Фундамент + флагманы (gate на апрув).** `tokens-v2.css` **в двух темах сразу**, новый шелл с theme-toggle, `stateful.js` + `components.js` + `fixtures.js`, `index.html`-атлас с `?theme=`, `manifest-v2.json`. Флагманские экраны: `chats` (3-pane, все состояния × обе темы), `tools` index, один campaign-флоу end-to-end (pivot → per-lady → create). **→ твой апрув направления до массового роллаута.**
- **Phase B — Workspace:** mails, history, omniscience.
- **Phase C — Campaigns:** консолидированная зона, ~13 экранов.
- **Phase D — Tools:** ~9 экранов.
- **Phase E — Admin:** ~10 экранов.
- **Phase F — Public + statistics:** login, statistics.
- **Phase G — Vision «new in v2»:** ~6 экранов/состояний из §5 — строятся на уже готовых зонах; при питч-показе можно выдвинуть раньше по запросу.
- **Phase H — Верификация и полировка:** аудит ссылок/ассетов/тегов, покрытие манифеста (каждый v1-роут → v2), state-матрица × 2 темы зелёная, контраст AA на всех состояниях в обеих темах, keyboard/focus, before/after ссылки на design-copy.

## 7. Acceptance checks (definition of done)

- [ ] Каждый экран открывается из атласа, каждое состояние переключается чипами и deep-link'ом `?screen=&state=`.
- [ ] Каждый экран и каждое состояние работают в light и dark: `?theme=` пробрасывается в iframe, тогл есть в шелле и в атласе.
- [ ] `manifest-v2.json` покрывает 100% роутов `design-copy/manifest.json` (route → file+state, или пометка «consolidated into …»).
- [ ] Каждый экран несёт канонический набор состояний своего типа + доменные; пустых/заглушечных view нет.
- [ ] Все 6 vision-позиций из §5 построены и помечены «new in v2» в атласе и `vision: true` в манифесте.
- [ ] 0 битых ссылок/ассетов, 0 несбалансированных тегов, 0 undefined CSS-переменных — тем же аудит-скриптом, что для v1.
- [ ] Контраст ≥4.5:1 на тексте во всех состояниях **в обеих темах** (включая hover/disabled/error); фокус-ринг на каждом интерактиве.
- [ ] Один акцент `#5862de`; `#6366f1` не появляется; emoji не используются как иконки; платформенные лого — из assets как есть. Тёмная палитра — только derived из зарегистрированных токенов, без новых hex.
- [ ] v1 `design-copy/` не изменён — before/after работает.
